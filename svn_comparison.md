# Сравнение Git и SVN

## 1. Почему в Git ветвление дешёвое, а в SVN дорогое?

В Git ветка - это лёгкий указатель на коммит. Создание и переключение ветки обычно меняет только такой указатель и локальное рабочее дерево, поэтому операция выполняется быстро и почти не занимает дополнительного места.

В традиционном SVN ветка создаётся как копия каталога репозитория. Сервер умеет делать такую копию эффективно, но дальнейшая работа с ветками и их слияние сильнее зависят от структуры централизованного репозитория и сетевого взаимодействия. Поэтому ветвление в SVN организационно тяжелее и применяется реже.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, если центральный SVN-сервер недоступен. Коммит в SVN сразу записывает изменения в центральный репозиторий, поэтому клиенту требуется сетевое соединение с сервером. Локально можно продолжать редактировать файлы и смотреть часть состояния рабочей копии, но создать полноценный коммит нельзя.

В Git каждый клон содержит локальный репозиторий с историей. Поэтому коммиты, ветки и просмотр истории доступны офлайн, а сеть нужна только для обмена изменениями через `push`, `fetch` или `pull`.

## 3. Когда SVN всё ещё может быть предпочтительнее Git?

SVN может быть удобен в проектах с крупными бинарными файлами и централизованной моделью доступа, особенно если нужны блокировки файлов перед редактированием. Он также остаётся оправданным в существующих корпоративных и государственных системах, где уже настроены процессы, интеграции, резервное копирование и разграничение доступа по каталогам. Переход на Git в таких случаях может стоить дороже, чем дальнейшая поддержка SVN.
